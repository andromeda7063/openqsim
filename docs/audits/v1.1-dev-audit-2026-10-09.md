**OpenQSim audit — 9 October 2026**

Audited `v1.1/dev` at `c520560`, including the 17 commits after `dev` (`db7180b`), all production layers, tests, documentation, and local Git configuration/history. The checkout was clean at the start. This is an audit: no product code, requirements, dependencies, or Git history was changed.

**Assessment:** v1.1 has two confirmed regressions that should be fixed before release: loss of unapplied QASM text and silently cancelled moves into newly revealed columns. Several inherited interaction, input-handling, and visualization bugs also remain. The existing tests pass, but they do not exercise the failing cases below. CI and the traceability report provide less assurance than their presentation suggests.

Priorities: **P1** = fix before releasing v1.1; **P2** = actionable correctness or verification defect; **P3** = documentation or visual polish. Findings are grouped by root cause, so the 13 failing regression cases do not represent 13 separate bugs.

**1. [P1] Run, Save, and snapshot navigation erase unapplied QASM edits — introduced in v1.1**

Source: [qasm_panel.py:87](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/qasm_panel.py:87).

The QASM panel subscribes to the general session `changed` signal and calls `setPlainText(export_text(...))` for every notification. That includes successful Run, Save, and selecting a stored simulation step, although none changes the circuit. A user can append a valid instruction, click Run or Save, and lose the instruction without warning. `setPlainText` also clears the text editor's undo history, so local Undo cannot recover it.

Reproduced separately for Run, Save As, and Next-step navigation: the draft's appended `x q[1];` disappeared in each case. The initial implementation is commit `1c9a24f`.

Repair: synchronize on circuit replacement/change rather than every state notification; retain text, cursor, and undo history during status-only updates. Define how genuinely conflicting circuit edits interact with an unapplied draft. Add event-level tests for Run, Save, navigation, and draft recovery. Relevant requirement: FR-7.8; session-only actions are distinguished by LC-6 and LC-7.

**2. [P1] Dragging a gate into newly revealed columns silently cancels the move — introduced in v1.1**

Source: [circuit_canvas.py:487](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/circuit_canvas.py:487).

On mouse release, `_clear_temporary_columns()` shrinks the canvas before `self.rect().contains(pt)` checks the release position. The position was valid in the expanded canvas, but is now outside the shrunken widget. The handler returns without committing or reporting an error.

Reproduction: with a 300-pixel scroll area and an X gate at column 0, drag toward the right edge until additional columns appear, then release over column 10. The preview is valid and identifies column 10; the gate remains at column 0. This was verified through the canvas press/move/release handlers, with the preview checked before release. The regression arises from `2ac831f` adding temporary-column cleanup ahead of the bounds check added by `dee390b`.

Repair: determine release validity using the geometry before cleanup, commit the validated move, then remove unused temporary columns. Test the full release sequence after edge scrolling, including rejection and cancellation. Requirements: FR-1.7, FR-1.53–FR-1.56, NFR-2.7.

**3. [P2] Ctrl-click does not toggle gate selection — inherited from v1.0**

Sources: [selection_controller.py:212](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/selection_controller.py:212), [selection_controller.py:278](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/selection_controller.py:278).

The canvas uses the drag initiation/completion path, not the `click_cell()` helper tested by the Ctrl-click unit test. Pressing an already selected gate bypasses toggling. Pressing an unselected gate with Ctrl temporarily adds it, but release collapses a multi-selection to that gate with `ctrl=False`.

Actual Qt mouse-click reproduction: click H, Ctrl-click X → only X remains selected; Ctrl-click X again → X remains selected. Both add and remove assertions fail. The relevant implementation dates to `d185b04`.

Repair: retain the click's modifier/selection intent until release and distinguish click from actual drag. Test complete press/release sequences, including multi-qubit gates. Requirements: FR-1.21, FR-1.23, NFR-2.6.

**4. [P2] Malformed file inputs bypass standard error handling — inherited from v1.0**

Sources: [qcs.py:184](/home/andromeda/Documents/code/projects/openqsim/libqsim/src/libqsim/persistence/qcs.py:184), [session.py:314](/home/andromeda/Documents/code/projects/openqsim/libqsim/src/libqsim/application/session.py:314), [qcs.py:48](/home/andromeda/Documents/code/projects/openqsim/libqsim/src/libqsim/persistence/qcs.py:48), [importer.py:139](/home/andromeda/Documents/code/projects/openqsim/libqsim/src/libqsim/qasm/importer.py:139).

A `.qcs` or `.qasm` file containing invalid UTF-8 bytes raises `UnicodeDecodeError` out of `EditorSession.open()` / `import_qasm()`. The file-reading code catches `OSError`, which does not catch decoding failures. The JSON parser's decoding-error catch is too late because file decoding has already occurred.

Also, a 5,000-digit integer in QCS or a QASM register declaration raises Python's integer-conversion `ValueError` instead of `QcsError` / `QasmError`. All four cases were reproduced. These exceptions escape the command layer's normal error outcome; GUI process termination was not established, so this is reported as unhandled exceptions and missing user-facing errors, not a proven whole-process crash.

Repair: translate decoding and bounded numeric parsing failures at the persistence/interoperability boundary into concise format errors. Verify that circuit, baseline, history, retained results, trace, and selected step survive failed Open/Import. Requirements: NFR-3.1, NFR-3.5, LC-11, FR-5.15–FR-5.18.

**5. [P2] Histogram hover can identify the wrong basis state and probability — inherited, exposed by the v1.1 layout**

Sources: [histogram_view.py:45](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/histogram_view.py:45), [histogram_view.py:105](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/histogram_view.py:105).

Bars have a minimum width of one pixel even when their spacing is less than one pixel. Hover testing converts the pointer to integer coordinates and chooses the first overlapping bar. At the reference 1920×1080 window size, the histogram is 940 pixels wide: only 880 of 1,024 states can be reached by the current horizontal hover mapping.

Reproduction: use 10 qubits, apply X only to q0, and Run. Hovering at the center of the probability-one bar for `0000000001` yields `|0000000000⟩: 0.0000`. This is a misleading numerical readout, not merely crowded labels. Existing layout tests check bar counts, not event-level identification.

Repair: remove overlapping hit regions and provide sufficient horizontal resolution, scrolling, or another exact-value inspection path for all 1,024 states. Add a hover regression for adjacent states at the actual results-panel width. Relevant requirements: FR-4.7–FR-4.9 and the UI's advertised exact-value hover behavior.

**6. [P2] QASM file import and the embedded editor recognize inconsistent syntax — inherited parser defects**

Sources: [importer.py:109](/home/andromeda/Documents/code/projects/openqsim/libqsim/src/libqsim/qasm/importer.py:109), [importer.py:131](/home/andromeda/Documents/code/projects/openqsim/libqsim/src/libqsim/qasm/importer.py:131), [importer.py:168](/home/andromeda/Documents/code/projects/openqsim/libqsim/src/libqsim/qasm/importer.py:168).

The documented whitespace-insensitive subset rejects `qreg q [ 2 ];` and `h q [ 0 ];` because its operand regexes require adjacent tokens. Conversely, gate dispatch lowercases input, so the file importer accepts `H q[0];` even though the supported syntax requires lowercase names. The v1.1 panel first runs Qiskit's strict syntax parser, so an uppercase program accepted through File → Import is rejected when entered in the panel.

Both whitespace rejection and uppercase acceptance were reproduced. Repair the subset parser's lexical handling and use shared fixtures through both entry paths. Do not loosen the supported gate set. Requirements: FR-6.1, FR-6.2, FR-6.14; [documented syntax](/home/andromeda/Documents/code/projects/openqsim/docs/qasm-support.md:28).

**7. [P2] Scrolling hides rejection feedback and wire identities — partly introduced in v1.1**

Sources: [circuit_canvas.py:703](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/circuit_canvas.py:703), [circuit_canvas.py:668](/home/andromeda/Documents/code/projects/openqsim/qsim-gui/src/qsim_gui/widgets/circuit_canvas.py:668).

Rejection text is drawn at the canvas origin, rather than at the visible viewport's origin. Place a gate at column 49, scroll right, and preview another gate on the occupied cell. The candidate is rejected, but the reason is offscreen. In the measured layout the horizontal offset is 1,080 pixels, while the entire rejection string ends around canvas x=581. The q0/q1 labels also scroll completely out of view.

[Rendered evidence](/home/andromeda/.codex/visualizations/2026/10/09/01a121a9-d4bb-7603-8c6e-b29e501891db/openqsim-audit/invalid-scrolled.png) shows the invalid cue with no visible reason or wire labels. Feedback is new in v1.1; the non-sticky wire labels predate it.

Repair: anchor feedback to the viewport or a persistent status area, and retain visible wire indices while horizontally scrolling. Verify combined horizontal/vertical scrolling. Requirements: FR-1.54, NFR-2.5, NFR-2.7.

**8. [P2] CI excludes v1.1 development and omits 160 existing tests**

Sources: [ci.yml:3](/home/andromeda/Documents/code/projects/openqsim/.github/workflows/ci.yml:3), [ci.yml:42](/home/andromeda/Documents/code/projects/openqsim/.github/workflows/ci.yml:42), [pyproject.toml:12](/home/andromeda/Documents/code/projects/openqsim/pyproject.toml:12).

Push and pull-request base filters cover only `main` and `dev`. A push to `v1.1/dev`, or a PR targeting it, does not match this workflow. A PR from v1.1 targeting main/dev would match. Even when triggered, the workflow runs only `libqsim/tests` plus two spikes; it never runs the 138 GUI or 22 acceptance cases.

Additionally, plain `uv run pytest` collects only core tests because `testpaths` is restricted. The documented pre-commit sequence adds GUI tests separately but still omits acceptance tests. This gap predates v1.1, but it is particularly consequential for the new GUI work.

Repair: cover supported development branches and explicitly run core, offscreen GUI, and acceptance suites with the lockfile enforced. Keep native Wayland acceptance separate from offscreen CI. This finding is based on the checked-in workflow, not remote Actions logs or branch-protection inspection.

**9. [P2] Traceability silently omits five v1.1 requirements and has stale totals**

Sources: [trace_report.py:48](/home/andromeda/Documents/code/projects/openqsim/tools/trace_report.py:48), [requirements.md:1249](/home/andromeda/Documents/code/projects/openqsim/docs/requirements.md:1249), [traceability-report.md:5](/home/andromeda/Documents/code/projects/openqsim/docs/traceability-report.md:5).

The generator recognizes FR/NFR rows only if the first line ends in a priority. FR-7.6 through FR-7.10 have no such priority and are silently excluded. They do have marked tests; the defect is that they disappear from the denominator and coverage-gap checks. Priority assignment needs an explicit requirements decision rather than an inferred edit.

The saved report says 202 requirements and 340 tests. Current collection finds 376 tests, and the parser finds 210 requirements before those five omitted IDs. NFR-2.8 currently has no pytest marker and is described as manual acceptance. A test marker is a traceability link, not proof of compliance: the Ctrl-click finding demonstrates that distinction.

Repair: reject or explicitly report unparsed requirement definitions, fail on collection errors, regenerate current totals, and separate automated test links from recorded manual acceptance evidence. No requirements were edited during this audit.

**10. [P2] The release acceptance procedure tests obsolete or nonexistent behavior**

Sources: [acceptance-checklist.md:17](/home/andromeda/Documents/code/projects/openqsim/docs/acceptance-checklist.md:17), [line 42](/home/andromeda/Documents/code/projects/openqsim/docs/acceptance-checklist.md:42), [line 77](/home/andromeda/Documents/code/projects/openqsim/docs/acceptance-checklist.md:77), [line 140](/home/andromeda/Documents/code/projects/openqsim/docs/acceptance-checklist.md:140).

The checklist currently directs testers to:

- Launch with `uv run python -m qsim_gui`; this fails because there is no `qsim_gui.__main__`. The README's `uv run python -m qsim_gui.app` is the implemented module entry point.
- Use Ctrl+R, although Run has no such shortcut.
- Expect Run to select the initial snapshot and expose Next; that is now Step Run's behavior.
- Reset one sphere independently using Reset View; the current single control resets all spheres.
- Expect every circuit PNG to contain all 50 columns; the current exporter captures the revealed canvas extent.

These inconsistencies prevent reliable manual sign-off and can make correct current behavior appear broken. Update the checklist against the authoritative v1.1 requirements and then record actual native-platform execution. Do not change product behavior just to satisfy stale checklist text.
